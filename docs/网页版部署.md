# 部署到 GitHub Pages（网页版）

把工作台做成**打开网址就能用**的纯前端应用，数据存在访问者自己的浏览器里。

---

## 一、两种运行方式的区别

工作台支持两种运行方式，同一套代码自动切换：

| | 本地版（Python 后端） | 网页版（纯前端） |
|---|---|---|
| 启动方式 | 双击 `启动工作台.bat` | 打开网址 |
| 需要 Python | 是 | 否 |
| 数据存哪 | `data/*.json` 文件 | 浏览器 localStorage |
| 数据共享 | 同机共享 | 各浏览器独立 |
| 适合场景 | 自己录入管理、数据量大 | 演示、给领导看、随时访问 |

**自动检测**：页面加载时会尝试连后端，连不上就用纯前端模式，无需手动切换。

---

## 二、网页版怎么用

打开网址后：

- **数据**：从 `web/data/bundle.js` 载入初始数据，之后所有修改存在浏览器 localStorage
- **侧栏底部**：多一个「数据管理」按钮，可以导出/导入/重置数据
- **顶栏**：显示「数据存于本浏览器」

### 重要：数据只在你自己的浏览器里

- 换电脑、换浏览器、清缓存 → 数据不同步
- 你录的数据别人看不到（除非导出给他）
- 建议定期点「数据管理 → 导出全部数据」备份

### 统一录入的正确姿势

你说过「我统一录入数据」，推荐这个流程：

1. **本地用 Python 版录入**（数据存 `data/*.json`，稳定可靠）
2. 录完执行 `python app/build_static.py` 生成新数据包
3. 提交推送，网页版自动更新
4. 其他人打开网址看到的就是最新数据

这样网页版是「发布用」，本地版是「工作用」。

## 三、首次部署步骤

### 第 1 步：生成数据包

```bash
# 用当前真实数据（本地版录入的数据）
python app/build_static.py

# 或生成演示数据（对外演示用）
python app/build_static.py --demo
```

生成 `web/data/bundle.js`。

### 第 2 步：提交推送

```bash
git add web/data/bundle.js
git commit -m "更新数据包"
git push
```

### 第 3 步：在 GitHub 上开启 Pages

1. 打开仓库 `https://github.com/XueZhi024/EHS-wordbench`
2. 点 **Settings**（设置）
3. 左侧菜单找到 **Pages**
4. **Source** 选 `Deploy from a branch`
5. **Branch** 选 `main`，目录选 **`/docs`** 或 **`/ (root)`**

⚠️ **关键**：如果选 `/ (root)`，访问地址是 `https://xuezhi024.github.io/EHS-wordbench/web/`；
如果选 `/docs`，需要把 web 目录内容放进去。

**推荐做法**：仓库根目录已经有一个 `index.html` 跳转文件，指向 `web/`。
这样选 `/ (root)` 时，打开 `https://xuezhi024.github.io/EHS-wordbench/` 会自动跳到 `web/`。

6. 点 **Save**
7. 等 1-2 分钟，页面顶部会显示访问地址

### 第 4 步：访问

```
https://xuezhi024.github.io/EHS-wordbench/
```

## 四、更新数据后如何发布

每次在本地录入新数据后：

```bash
python app/build_static.py    # 重新生成数据包
git add web/data/bundle.js
git commit -m "更新数据：新增 N 条"
git push
```

GitHub Pages 会自动重新部署，1 分钟左右生效。

**注意**：已经打开过网页的浏览器不会自动拉新数据（因为 localStorage 里有旧数据）。
需要点「数据管理 → 恢复初始数据」才能看到新数据包的内容。

## 五、数据包里放什么

`python app/build_static.py` 导出的是**当前 `data/` 目录的全部数据**。

⚠️ **如果仓库是公开的，注意别把真实敏感数据传上去**：

- 员工真实姓名
- 事故详细描述
- 医疗费用
- 承包商联系方式

**建议做法**：

| 仓库类型 | 数据包内容 |
|---|---|
| 公开仓库 | 用 `--demo` 生成演示数据 |
| 私有仓库 | 可以用真实数据 |

如果要用真实数据又不想公开，有两个办法：

1. 把仓库改成 **Private**（GitHub 免费账号也支持私有仓库 + Pages）
2. 保持公开，但数据包用演示数据，真实数据只在本地版使用

## 六、常见问题

**Q：网页版能多人同时录入吗？**
不能。每个浏览器独立存储，互不影响。需要多人协同要用 Python 后端版。

**Q：数据会丢吗？**
清浏览器数据会丢。所以务必定期「导出全部数据」备份。

**Q：能改成本地存文件的吗？**
浏览器安全限制，网页不能直接写本地文件。只能存 localStorage 或导出下载。

**Q：手机上能用吗？**
可以，页面是响应式的。但手机浏览器清缓存也会丢数据。

**Q：GitHub Pages 有访问限制吗？**
公开仓库无限制。私有仓库的 Pages 需要 GitHub Pro 才能对外访问（免费账号的私有仓库 Pages 只有自己登录能看）。

**Q：多久生效？**
推送后通常 1-2 分钟。可以在仓库的 **Actions** 标签页看部署进度。

**Q：想用自己的域名？**
Settings → Pages → Custom domain，填入域名并在 DNS 加 CNAME 记录。

## 七、目录结构说明

```
仓库根目录/
├── index.html          ← 跳转页，自动跳到 web/
├── web/
│   ├── index.html      ← 应用主页面
│   ├── app.js          ← 前端逻辑（自动检测运行模式）
│   ├── localapi.js     ← 纯前端数据层（localStorage）
│   ├── charts.js       ← 图表绘制
│   ├── styles.css      ← 样式
│   └── data/
│       └── bundle.js   ← 数据包（由 build_static.py 生成）
├── app/                ← Python 后端（本地版用，Pages 不执行）
└── data/               ← 本地版数据（.gitignore 已排除）
```
