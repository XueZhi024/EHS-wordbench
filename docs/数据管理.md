## 二、文件长什么样

每个文件是一个 JSON，结构统一：

```json
{
  "collection": "hazards",
  "version": 1,
  "seq": 18,
  "updatedAt": "2026-11-05 11:56:27",
  "items": [
    {
      "id": "YH-2026-0001",
      "title": "三车间东侧配电箱门锁损坏，箱门无法锁闭",
      "category": "电气安全",
      "level": "一般隐患",
      "source": "日常巡检",
      "foundDate": "2026-09-22",
      "foundBy": "张建国",
      "dept": "生产部",
      "location": "生产车间",
      "description": "三车间东侧配电箱门锁损坏，箱门无法锁闭。",
      "measure": "更换门锁并加装防误碰挡板",
      "responsible": "张建国",
      "deadline": "2026-10-16",
      "status": "已关闭",
      "rectifyDate": "2026-10-14",
      "rectifyNote": "已按措施完成整改。",
      "cost": 5000,
      "checkDate": "2026-10-15",
      "checkBy": "陈志强",
      "checkResult": "通过",
      "remark": "",
      "createdAt": "2026-11-03 20:11:33",
      "updatedAt": "2026-11-03 20:11:33",
      "overdue": false
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `collection` | 模块标识，如 `hazards` |
| `version` | 文件格式版本，固定 `1` |
| `seq` | 当前流水号（编号最后 4 位，如 `seq: 18` 表示下一个新编号是 `YH-2026-0019`） |
| `updatedAt` | 文件最后修改时间 |
| `items` | 记录数组，每条记录就是一行数据 |
| `id` | 系统生成的编号，**不要手动修改** |
| `createdAt` / `updatedAt` | 记录的创建与更新时间，系统自动维护 |
| `overdue` 等计算字段 | 读取时实时计算并附带，**不需要手动维护**，改了也没用 |

## 三、怎么更新数据

有 5 种方式，按推荐程度排序：

### ✅ 方式一：界面录入（最推荐）

打开工作台 → 左侧选模块 → 右上角「＋ 新增」或点行末「编辑」。

**优点**：自动校验必填项、枚举值、日期格式；自动计算派生字段（风险值、到期天数、逾期状态）；自动生成编号；自动备份。

**这是日常使用的主要方式。**

### ✅ 方式二：Excel 批量导入

适合一次性录入几十上百条。

1. 模块页面点「下载模板」→ 得到标准表头的 Excel
2. 在 Excel 里填数据（**不要改表头文字**）
3. 点「导入 Excel」→ 选文件 → 开始导入

**导入规则**：

| 编号列 | 结果 |
|---|---|
| 留空 | 新增一条，自动生成编号 |
| 填已有编号 | **更新**该条记录 |
| 填不存在的编号 | 跳过并报错 |

**优点**：同样走校验和备份，比手改 JSON 安全得多。

### ⚠️ 方式三：直接编辑 JSON 文件

**仅在特殊情况下使用**（如批量修正某个字段、程序出错时的应急处理）。

步骤：
1. **先关闭工作台服务**（关掉黑色命令行窗口）
2. 用记事本或 VS Code 打开对应 `.json` 文件
3. 修改内容
4. **保存前先备份**：复制一份改名为 `xxx.json.bak`
5. 保存后重新启动工作台

**注意事项**：
- ⚠️ 必须保持 JSON 格式正确（逗号、引号、括号），否则文件会读取失败
- ⚠️ 不要修改 `id` 字段
- ⚠️ 不要在服务运行时改文件（会被覆盖或冲突）
- ⚠️ 直接改文件**不会**触发校验，填错的值会被原样保存

### ✅ 方式四：恢复备份

`data/backup/` 里有自动备份，每个模块保留最近 20 份。

恢复步骤：
1. 关闭服务
2. 把 `backup/hazards-20261105-115555.json` 这类文件复制到 `data/` 并改名为 `hazards.json`
3. 重启服务

### ✅ 方式五：导入别人给的完整备份

左下角「备份全部数据」下载的是 zip 包，解压后覆盖 `data/` 目录即可（覆盖前请先备份当前数据）。

## 四、自动备份机制

### 什么时候备份

每次写操作（新增/编辑/删除/导入）前，如果距上次备份**超过 10 分钟**，就会自动把原文件复制到 `backup/`。

### 保留多少

每个模块保留最近 **20 份**，超过的自动删除最旧的。

### 命名规则

```
hazards-20261105-115555.json
  模块名    日期     时分秒
```

### 手动备份（推荐定期做）

**方式一**：点界面左下角「备份全部数据」→ 下载 zip → 存到 U 盘或网盘。

**方式二**：直接复制整个 `data/` 文件夹。

## 五、重要提醒

### ⚠️ 这个目录在百度网盘同步范围内

路径是 `E:\BaiduSyncdisk\...`，说明**数据会自动同步到百度网盘**。

**好处**：多一层备份，换电脑能拿到数据。

**风险**：
- 如果网盘在服务写入时占用文件，可能报「拒绝访问」——程序已做重试处理，但偶尔仍会失败
- 多台电脑同步同一份数据可能冲突
- 安全数据上云需符合公司规定

**建议**：如果不希望数据上云，把整个工作台目录移到 `E:\安全管理数据工作台\` 这类非同步目录，或关闭该文件夹的同步。

### ⚠️ 不要用 Excel 直接打开 JSON 文件

Excel 会把它当文本，改完保存会破坏格式。用**记事本**或 **VS Code**。

### ⚠️ 服务运行时不要改文件

程序在内存里维护数据，改文件后可能被覆盖。**先关服务，再改文件，再启服务。**

## 七、数据安全建议

1. **每周备份一次**：点「备份全部数据」，把 zip 存到别的磁盘
2. **每月归档一次**：导出一份 HTML 报表存到 `reports/` 或公司文档系统
3. **不要只依赖网盘同步**：同步可能冲突或失败，本地备份更可靠
4. **离职交接**：把整个工作台文件夹（含 `data/`）交接，不只是数据文件
