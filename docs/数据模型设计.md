## 一、总体设计

### 1.1 定位

单机运行的安全管理数据工作台：本地 Python 标准库提供 HTTP 服务，浏览器打开即用，数据以 JSON 文件形式保存在本机 `data/` 目录，支持 Excel 导入导出。**不依赖外网、不依赖第三方前端库、不需要安装数据库**。

### 1.2 架构

```
浏览器 (web/ 原生 HTML+JS+CSS)
        │  fetch JSON
        ▼
本地服务 app/server.py (http.server，仅监听 127.0.0.1)
        │
        ├── schema.py     集合与字段定义（唯一真源）
        ├── store.py      JSON 读写 + 主键自增 + 并发保护
        ├── excel.py      openpyxl 导入导出
        └── dashboard.py  KPI 聚合计算
        ▼
data/*.json (每个集合一个文件)
```

**关键约定**：`app/schema.py` 是字段定义的唯一真源。前端通过 `GET /api/schema` 拿到全部字段定义后**通用渲染**列表和表单，因此新增字段只需改 schema.py 一处，前端无需改动。

### 1.3 目录结构

```
安全管理数据工作台/
├── 启动工作台.bat          双击启动，自动打开浏览器
├── README.md              一页纸说明
├── docs/
│   ├── 数据模型设计.md     本文
│   └── 使用说明.md         操作手册（第 7 步产出）
├── app/
│   ├── server.py          HTTP 服务与路由
│   ├── schema.py          集合与字段定义
│   ├── store.py           JSON 存储层
│   ├── excel.py           Excel 导入导出
│   ├── dashboard.py       KPI 聚合
│   └── selftest.py        自检脚本
├── web/
│   ├── index.html         单页外壳
│   ├── styles.css         样式
│   ├── app.js             路由、通用列表/表单、各模块交互
│   └── charts.js          Canvas 手绘图表
└── data/                  业务数据（可整体备份）
    ├── hazards.json
    ├── ...

```

## 二、字段类型规范

前端表单控件与后端校验均按此类型渲染。

| 类型 | 说明 | 存储格式 | 表单控件 |
|---|---|---|---|
| `text` | 单行文本 | 字符串 | 单行输入框 |
| `textarea` | 多行文本 | 字符串 | 多行文本框 |
| `number` | 数值 | 数字（无值存 `null`） | 数字输入框 |
| `date` | 日期 | `YYYY-MM-DD` | 日期选择器 |
| `datetime` | 日期时间 | `YYYY-MM-DD HH:mm` | 日期 + 时间选择器 |
| `select` | 单选枚举 | 字符串（须在 options 内） | 下拉框 |
| `bool` | 是/否 | `true` / `false` | 勾选框 |
| `computed` | 自动计算 | 数字或字符串 | 只读展示，服务端计算 |
| `id` | 自动编号 | 字符串 `前缀-YYYY-NNNN` | 只读展示 |

字段定义结构（`schema.py` 中每个字段是一个 dict）：

```python
{
  "key": "title",          # 存储键名，英文字段名
  "label": "隐患描述",      # 界面中文名
  "type": "text",          # 上表类型
  "required": True,        # 是否必填
  "options": [...],        # select 类型的候选值
  "default": "",           # 新建时的默认值
  "in_list": True,         # 是否在列表页作为一列显示
  "width": 160,            # 列宽（px）
  "help": "填写说明",       # 表单下方提示
  "computed": "表达式名",   # computed 类型使用的计算器名
}
```

### 2.1 通用字段（每个集合都有）

| key | label | 类型 | 说明 |
|---|---|---|---|
| `id` | 编号 | `id` | 服务端生成，格式 `前缀-年份-4位序号`，如 `YH-2026-0001`；不可修改 |

| `updatedAt` | 更新时间 | `datetime` | 服务端写入，自动 |
| `remark` | 备注 | `textarea` | 选填 |

## 三、模块数据模型

### 3.1 隐患排查治理 `hazards`

**业务闭环**：排查发现 → 登记 → 整改 → 验收 → 关闭；验收不通过退回整改。

| key | 中文名 | 类型 | 必填 | 枚举 / 说明 |
|---|---|---|---|---|
| id | 隐患编号 | id | — | YH-YYYY-NNNN |
| title | 隐患描述 | text | ✔ | 一句话说清问题，如「三车间东侧配电箱门锁损坏」 |
| category | 隐患类别 | select | ✔ | 设备设施 / 作业行为 / 消防安全 / 电气安全 / 危化品 / 职业健康 / 环境管理 / 管理缺陷 / 其他 |
| level | 隐患等级 | select | ✔ | 一般隐患 / 重大隐患 |
| source | 发现来源 | select | ✔ | 日常巡检 / 专项检查 / 节前检查 / 上级检查 / 第三方检查 / 员工举报 / 班组自查 |
| foundDate | 发现日期 | date | ✔ | |
| foundBy | 发现人 | text | | |
| dept | 责任部门 | select | ✔ | 取自部门字典 |
| location | 所在位置 | text | | 厂区 / 车间 / 具体位置 |
| description | 详细描述 | textarea | | 现场情况、可能后果 |
| measure | 整改措施 | textarea | | 计划采取的措施 |
| responsible | 整改责任人 | text | ✔ | |
| deadline | 整改期限 | date | ✔ | 逾期判定基准 |
| status | 状态 | select | ✔ | 待整改 / 整改中 / 待验收 / 已关闭（默认「待整改」） |
| rectifyDate | 整改完成日期 | date | | 状态进入「待验收」时必填 |
| rectifyNote | 整改情况说明 | textarea | | |
| cost | 整改投入(元) | number | | |
| checkDate | 验收日期 | date | | |
| checkBy | 验收人 | text | | |
| checkResult | 验收结果 | select | | 通过 / 不通过 |
| overdue | 是否逾期 | computed | — | 未关闭且 `deadline < 今天` 即为逾期 |

**状态机**

```
        登记
          ▼
      待整改 ──开始整改──▶ 整改中 ──提交验收──▶ 待验收 ──验收通过──▶ 已关闭
                              ▲                    │
                              └────验收不通过───────┘
```

允许的操作与前置条件：

| 操作 | 当前状态 | 目标状态 | 附加要求 |
|---|---|---|---|
| 开始整改 | 待整改 | 整改中 | — |
| 提交验收 | 整改中 | 待验收 | `rectifyDate` 必填 |
| 验收通过 | 待验收 | 已关闭 | `checkResult=通过`，写入 `checkDate`、`checkBy` |
| 验收不通过 | 待验收 | 整改中 | `checkResult=不通过`，清空 `checkDate` |
| 撤销关闭 | 已关闭 | 待验收 | 需要备注原因 |

服务端对每次流转校验当前状态，非法流转返回 400。

### 3.2 风险分级管控 `risks`

**分级规则（LEC 简化法）**：风险值 `R = L × S`

| R 区间 | 风险等级 | 颜色 | 管控要求 |
|---|---|---|---|
| R ≥ 20 | 重大风险 | 红 | 立即整改，公司级管控，停产整顿 |
| 15 ≤ R < 20 | 较大风险 | 橙 | 限期整改，部门级管控 |
| 9 ≤ R < 15 | 一般风险 | 黄 | 计划整改，班组级管控 |
| R < 9 | 低风险 | 蓝 | 日常巡查，岗位级管控 |

| key | 中文名 | 类型 | 必填 | 枚举 / 说明 |
|---|---|---|---|---|
| id | 风险编号 | id | — | FX-YYYY-NNNN |
| riskPoint | 风险点名称 | text | ✔ | 如「三车间冲压工位」 |
| location | 所在区域 | text | | |
| activity | 作业活动/设备 | text | | |
| hazardFactor | 危险有害因素 | textarea | ✔ | 可能造成伤害的能量或物质 |
| accidentType | 可能导致的事故 | select | | 物体打击 / 车辆伤害 / 机械伤害 / 起重伤害 / 触电 / 淹溺 / 灼烫 / 火灾 / 高处坠落 / 坍塌 / 中毒和窒息 / 容器爆炸 / 其他伤害 |
| likelihood | 可能性 L | number | ✔ | 1–5 整数 |
| severity | 严重性 S | number | ✔ | 1–5 整数 |
| riskScore | 风险值 R | computed | — | `L × S`，服务端计算 |
| riskLevel | 风险等级 | computed | — | 按上表由 R 推出 |
| controlMeasures | 管控措施 | textarea | ✔ | 技术/管理/培训/个体防护/应急 |
| controlLevel | 管控层级 | select | ✔ | 公司级 / 部门级 / 班组级 / 岗位级 |
| dept | 责任部门 | select | ✔ | |
| responsible | 责任人 | text | | |
| checkFreq | 检查频次 | select | | 每班 / 每日 / 每周 / 每月 / 每季 / 每半年 / 每年 |
| lastCheckDate | 最近检查日期 | date | | |
| status | 受控状态 | select | ✔ | 受控 / 失控 / 整改中 / 已消除（默认「受控」） |

**派生计算**：`riskScore`、`riskLevel` 由服务端在保存时计算并回写，前端只读展示；保存后如果 L 或 S 改动，两者自动重算。

### 3.3 安全疑虑 `concerns`

**定位**：安全疑虑是员工反映的**主观安全顾虑**，尚未确认为问题。与隐患的区别：

| | 安全疑虑 | 隐患 |
|---|---|---|
| 性质 | 「我觉得这里不安全」 | 已确认的问题 |
| 来源 | 任何人（含匿名） | 检查、巡检 |
| 处理 | 先核实判断，再决定 | 直接整改 |
| 去向 | 属实 → 转隐患；不属实 → 说明后关闭 | 整改 → 验收 → 关闭 |

**业务闭环**

```
反映登记 → 待核实 → 核实中 ─┬─ 属实 ──→ 转隐患（填隐患编号，转入隐患排查治理）
                            └─ 不属实 → 答复并关闭（说明原因）
```

| key | 中文名 | 类型 | 必填 | 枚举 / 说明 |
|---|---|---|---|---|
| id | 编号 | id | — | AQ-YYYY-NNNN |
| title | 疑虑内容 | text | ✔ | 一句话说清顾虑 |
| status | 处理状态 | select | ✔ | 待核实 / 核实中 / 待答复 / 已关闭 / 已转隐患（默认「待核实」） |
| overdue | 超期 | computed | — | 未关闭/未转隐患且 `deadline < 今天` |
| replyState | 反馈 | computed | — | 已办结 / 已答复 / 待答复 |
| severity | 初步判断 | select | | 低 / 中 / 高（默认「中」） |
| category | 疑虑类别 | select | ✔ | 设备设施 / 作业行为 / 消防安全 / 电气安全 / 危化品 / 职业健康 / 环境管理 / 作业环境 / 管理缺陷 / 其他 |
| dept | 所属部门 | select | ✔ | 取自部门字典 |
| deadline | 处理时限 | date | ✔ | 承诺给反映人的答复期限，超期标红 |
| daysLeft | 剩余 | computed | — | `deadline - 今天`，负数表示已超期 |
| source | 反映渠道 | select | ✔ | 现场反映 / 班前会 / 意见箱 / 微信/电话 / 工会 / 安全员巡查 / 举报 / 其他 |
| reporter | 反映人 | text | | **可留空表示匿名反映** |
| reporterType | 反映人类型 | select | | 本厂员工 / 班组长 / 承包商人员 / 访客 / 匿名 |
| location | 涉及位置 | text | | |
| foundDate | 反映日期 | date | ✔ | |
| description | 详细描述 | textarea | | |
| verifyDate | 核实日期 | date | | |
| verifier | 核实人 | text | | |
| conclusion | 核实结论 | textarea | | 是否属实、可能后果 |
| replyDate | 答复日期 | date | | |
| replyContent | 答复内容 | textarea | | 向反映人反馈的处理意见 |
| handle | 处理措施 | textarea | | |
| hazardId | 转隐患编号 | text | | 转隐患后填写生成的隐患编号，便于追溯 |

**状态机**

| 操作 | 当前状态 | 目标状态 | 附加要求 |
|---|---|---|---|
| 开始核实 | 待核实 | 核实中 | — |
| 转隐患 | 待核实 / 核实中 | 已转隐患 | `conclusion` 和 `hazardId` 必填 |
| 答复并关闭 | 待核实 / 核实中 / 待答复 | 已关闭 | `replyDate` 和 `replyContent` 必填 |
| 退回待核实 | 核实中 / 待答复 | 待核实 | — |
| 重新打开 | 已关闭 / 已转隐患 | 待核实 | — |

**校验规则**
- 状态为「已转隐患」时，核实结论和隐患编号都必填——保证每条疑虑都能追溯到具体隐患
- 状态为「已关闭」时，必须有答复内容——保证反映人得到反馈
- 已关闭 / 已转隐患的疑虑不再计算超期

**设计说明**：转隐患不做自动创建，而是要求填写隐患编号。这样处理人必须先到「隐患排查治理」建好隐患（走完整的隐患登记流程），再把编号填回来。好处是隐患的责任人、期限、等级等必填项不会被跳过，链条清晰可查。

### 3.4 事故事件管理 `incidents`

按公司《事件等级划分标准》分 **6 大类**，其中 3 类细分为 **A/B/C 级**（详见 [事件等级标准](事件等级标准.md)）。

| key | 中文名 | 类型 | 必填 | 枚举 / 说明 |
|---|---|---|---|---|
| id | 事件编号 | id | — | SG-YYYY-NNNN |
| title | 事件名称 | text | ✔ | |
| level1 | 事件大类 | select | ✔ | 安全疑虑 / 未遂事件 / 一般事件 / 急救箱事件 / 医疗处置事件 / 一般事故（默认「未遂事件」） |
| grade | 细分等级 | select | 部分 | A级 / B级 / C级，仅急救箱/医疗处置/一般事故显示 |
| levelDesc | 等级说明 | computed | — | 按大类+等级自动显示判定标准 |
| type | 事件类型 | select | ✔ | 人身伤害 / 火灾爆炸 / 设备事故 / 交通事故 / 环境污染 / 职业病 / 未遂事件 / 险兆事件 / 其他 |
| occurDate | 发生时间 | datetime | ✔ | |
| location | 发生地点 | text | ✔ | |
| dept | 责任部门 | select | ✔ | |
| persons | 涉及人员 | text | | |
| injuryPart | 受伤部位 | text | | 仅急救箱/医疗处置/一般事故显示 |
| loss | 直接经济损失(元) | number | | |
| lossDays | 损失工日 | number | | 医疗处置/一般事件/一般事故/急救箱显示 |
| medicalCost | 医疗费用(元) | number | | 仅急救箱/医疗处置显示，急救箱指 1500 元以下 |
| cause | 直接原因 | textarea | ✔ | |
| rootCause | 根本原因 | textarea | | 管理/制度/培训层面 |
| measures | 纠正预防措施 | textarea | ✔ | |
| status | 处理状态 | select | ✔ | 调查中 / 整改中 / 已结案（默认「调查中」） |
| reportDate | 上报日期 | date | | |
| closeDate | 结案日期 | date | | |
| reporter | 报告人 | text | | |

**等级判定标准**

| 大类 | A 级 | B 级 | C 级 |
|---|---|---|---|
| 急救箱事件 | 需到医院检查，停工休假 3 天以内 | 需到医院清洗、消毒、清创、包扎 | 用急救箱物品处理，不影响工作 |
| 医疗处置事件 | 停工休假 15 天以上 | 停工休假 15 天以内（含） | 停工休假 3 天以内（含） |
| 一般事故 | 3 人以下死亡/3–10 人重伤/10 人以上轻伤/100–1000 万元 | 3 人以下重伤/3–10 人轻伤/10–100 万元 | 3 人以下轻伤/10 万元以下 |

**校验**：`closeDate` 不得早于 `occurDate`；状态为「已结案」时 `closeDate` 必填。

**条件显示**：`grade`、`injuryPart`、`medicalCost` 等字段通过 `showWhen` 按 `level1` 决定是否显示，隐藏字段不强制必填。

### 3.11 设备管理 `equipments`

设备台账，按**三大类**组织，用 `type` 字段自动归入 `category`：

| 大类 | 包含设备类型 | 管理重点 |
|---|---|---|
| 特种设备类 | 吊车、叉车、电梯、储气罐、锅炉、压力容器、起重机械 | 使用登记证、定期检验 |
| 表阀类 | 气包压力表、气罐压力表、安全阀、流量计 | 校验周期、校验结果 |
| 其他类 | 其他设备（空压机、除尘系统等） | 投用日期、制造单位 |

**设计说明**：三类设备共用一张表，靠 `category` 计算字段分组 + 表单条件显示（`showWhen`）区分字段。这样检验到期能统一统计，也避免三张表重复维护。

| key | 中文名 | 类型 | 必填 | 枚举 / 说明 |
|---|---|---|---|---|
| id | 设备编号 | id | — | SB-YYYY-NNNN |

| name | 设备名称 | text | ✔ | 如「桥式起重机 10t」 |
| code | 设备编号/铭牌号 | text | | 出厂编号或单位内部编号 |
| model | 规格型号 | text | | |
| location | 安装位置 | text | ✔ | |

| responsible | 责任人 | text | | |
| regCode | 使用登记证号 | text | 特种设备必填 | 仅特种设备类显示 |
| ratedLoad | 额定载荷 | text | | 吊车 / 叉车 / 起重机械 显示 |
| ratedSpeed | 额定速度 | text | | 电梯 显示 |
| capacity | 容积/容量 | text | | 储气罐 / 压力容器 显示 |

| range | 量程 | text | | 压力表 / 流量计 显示 |
| accuracy | 精度等级 | text | | 压力表 显示 |

| calibDate | 最近校验日期 | date | | 仅表阀类显示 |
| calibNext | 下次校验日期 | computed | — | `calibDate + calibCycle` |
| calibResult | 校验结果 | select | | 合格 / 不合格 / 待校验 |
| manufacturer | 制造单位 | text | | 仅其他类显示 |
| installDate | 投用日期 | date | | 仅其他类显示 |
| inspectExpire | 检验有效期至 | date | | 通用，到期提醒基准 |
| daysLeft | 剩余天数 | computed | — | `inspectExpire - 今天` |
| expiryWarn | 到期提醒 | computed | — | 已过期 / 30天内到期 / 正常 / 已停用 |
| status | 设备状态 | select | ✔ | 在用 / 备用 / 停用 / 维修中 / 已报废（默认「在用」） |

**条件显示机制（`showWhen`）**

字段可声明 `showWhen: {"key": "category", "in": ["特种设备类"]}`，前端按依赖字段的当前值决定是否显示该字段，后端校验时**跳过隐藏字段的必填判断**——所以叉车不会被要求填电梯的额定速度。

由于 `category` 是计算字段（表单里没有输入框），schema 额外下发 `computedMap` 让前端实时推算：

```json
"computedMap": {
  "category": {
    "source": "type",
    "map": {"吊车": "特种设备类", "叉车": "特种设备类", "...": "..."},
    "default": "其他类"
  }
}
```

**校验规则**

- 特种设备类：`regCode`、`nextInspectDate` 必填
- 表阀类：`calibCycle` 必填
- 状态为「已报废」时必须在备注说明原因与处置方式
- `expiryWarn`：`inspectExpire` 已过为「已过期」，30 天内为「30天内到期」；状态为停用/报废时不提醒（返回「已停用」）

**状态流转**：在用 ⇄ 备用 ⇄ 停用，在用/备用 → 维修中 → 在用，任意状态 → 已报废。

## 四、存储格式

### 4.1 文件布局

每个集合对应 `data/{collection}.json`：

```json
{
  "collection": "hazards",
  "version": 1,
  "seq": 12,
  "updatedAt": "2026-11-01 10:30:00",
  "items": [
    {
      "id": "YH-2026-0001",
      "title": "三车间东侧配电箱门锁损坏",
      "category": "电气安全",
      "level": "一般隐患",
      "source": "日常巡检",
      "foundDate": "2026-10-20",
      "foundBy": "张三",
      "dept": "生产部",
      "location": "三车间东侧",
      "description": "配电箱门锁损坏，箱门无法锁闭，存在触电风险。",
      "measure": "更换门锁并加装防误碰挡板",
      "responsible": "李四",
      "deadline": "2026-11-05",
      "status": "待验收",
      "rectifyDate": "2026-10-28",
      "rectifyNote": "已更换门锁，加装挡板。",
      "cost": 320,
      "checkDate": "",
      "checkBy": "",
      "checkResult": "",
      "remark": "",
      "createdAt": "2026-10-20 09:12:00",
      "updatedAt": "2026-10-28 16:40:00"
    }
  ]
}
```

### 4.2 编号生成规则

`seq` 为集合内当年流水号，生成规则：`前缀 + "-" + 当前年份 + "-" + 4位流水`。跨年时 `seq` 归零重新计数（按年份分别维护，实现为在读取时按年份过滤已有编号的最大值 + 1，避免跨年重置丢失）。

### 4.3 并发与安全

- 服务只监听 `127.0.0.1`，默认端口 `8765`，被占用时自动顺延到 `8766`、`8767`…
- 写入采用「临时文件 + 原子替换」（先写 `.tmp` 再 `os.replace`），避免中途断电损坏文件。
- 每次写操作前，若距上次备份超过 10 分钟，将原文件复制到 `data/backup/{collection}-{时间戳}.json`，保留最近 20 份。
- 单进程单线程处理请求，天然串行，无需锁。

## 五、接口约定

所有接口返回 JSON，成功 `{"ok": true, "data": ...}`，失败 `{"ok": false, "error": "错误说明"}` 并带对应 HTTP 状态码。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/schema` | 全部集合与字段定义 + 部门字典 |
| GET | `/api/{collection}?q=&page=&size=&sort=&dir=&{字段}=` | 分页查询；`q` 为全文模糊搜索；其余同名参数按等值过滤 |
| GET | `/api/{collection}/{id}` | 单条详情 |
| POST | `/api/{collection}` | 新建，返回含 `id` 的完整记录 |
| PUT | `/api/{collection}/{id}` | 更新（全量覆盖，服务端保留 `id`/`createdAt`） |
| DELETE | `/api/{collection}/{id}` | 删除 |
| POST | `/api/{collection}/{id}/transition` | 状态流转，body `{"action": "开始整改", "extra": {...}}` |
| POST | `/api/{collection}/import` | 导入 Excel：请求体为文件二进制，`X-Filename` 头传文件名；返回 `{inserted, updated, skipped, errors[]}` |
| GET | `/api/{collection}/export.xlsx` | 导出当前筛选结果为 xlsx |
| GET | `/api/{collection}/template.xlsx` | 下载导入模板（含表头与示例行） |
| GET | `/api/dashboard?from=&to=&dept=` | 看板 KPI 聚合数据 |
| GET | `/api/dicts` | 部门字典与枚举字典 |
| GET | `/api/backup` | 打包下载全部数据（zip） |
| GET | `/api/health` | 健康检查，返回版本与数据条数 |

分页返回：`{"ok": true, "data": {"items": [...], "total": 123, "page": 1, "size": 20}}`

## 七、权限与安全

- 单机单人使用，不设登录与权限体系（v1 范围）。
- 服务仅监听 `127.0.0.1`，局域网其他机器无法访问。
- 导入的 Excel 只读取单元格值，不执行宏；`.xls` 不支持，需另存为 `.xlsx`。
- 不使用身份证号等敏感个人信息，人员标识用工号。
